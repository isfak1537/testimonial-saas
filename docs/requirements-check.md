## Real gaps and known limitations

1. **FR-INB-06, concurrent change is untested.** The branch `testimonials.service.ts:129-133` (a row changed between read and write, answer 409 or 404) is not reached by any test. The randomised sequence tests (`testimonials.test.ts:507`) were read: they run requests one after another, so they prove the invariant for sequential actions only. The per-action `where` preconditions in `testimonials.repo.ts:120-174` and the database guard `testimonial_publish_guard` are what protect against a race; neither is tested under real concurrency.
2. **Browser behaviour is covered by chromium-only E2E**, run in CI (run 41239555561), not in this session. Firefox and WebKit are not run (`51 passed`, all `[chromium]`). The Wall's masonry layout is not asserted by any test (FR-WALL-06), and the widget's 10 s timeout has no test (FR-WID-02).
3. **SEC-07:** the limiter is per process and in memory, and no `trust proxy` setting exists. Behind a reverse proxy all visitors would share one rate-limit bucket (the proxy's address) until a hop count is configured. There is no test.
4. **FR-TEN-04 is a convention, not a guard.** Nothing fails if a new repository function omits `workspaceId`; protection comes from reviews and the cross-tenant tests that exist today.
5. **FR-TEN-05:** `OWNER` is the only role (`schema.prisma:16-18`), so the 403 path is only reachable in a unit test with a synthetic allowed-role list.
6. **FR-AUTH-04:** equal timing for known and unknown emails is by construction (dummy hash), not measured.
7. **FR-OPS-01:** the purge logic is tested; the CLI wrapper (`purge-deleted.ts`) and its output are not run by any test I opened.
8. **NFR-06:** GitHub branch protection was not checked, so "pass in CI before an increment is accepted" is shown by CI history, not by an enforced rule.
9. **Database vs. docs:** `Space.prompts` is nullable in PostgreSQL (`migration.sql:58`) even though the API always returns an array; the mappers cover null (`public.mappers.ts:23`). Not an SRS conflict, but the SRS data model should be read with that in mind.
